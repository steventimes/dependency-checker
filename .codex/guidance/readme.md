## README 写作与维护约定

每次创建、重写或修改本仓库任意层级的 README（含各语言版本），都应用本节。
参考 [awesome-readme](https://github.com/matiassingers/awesome-readme/blob/67494300e0a6e3df6c6b50913b93207db90798b4/readme.md)
中反复出现的清晰简介、实际演示、易用安装、示例与导航。它是案例集，不是统一模板。
本节同时保留本项目评审中的证据边界，具体事实始终以当前源码和验证结果为准。

- 先读当前 README、包或构建配置、相关源码、CI 与已有文档，再改文案。
  面向第一次访问的使用者，开头讲清解决什么问题、适合谁、能得到什么结果。
  能力用实际任务说明，必要时交代为什么选择它，以及何时更适合其他方案。
- 在靠前位置提供最短可用路径，写明必要版本、依赖、工作目录、配置与运行入口。
  库给最小真实示例及预期输出，CLI 给调用与结果，应用给启动与首个可完成任务。
  区分已发布包、源码候选、可选依赖和开发环境，不把工作区能力写成发布版能力。
- 按读者任务组织简介、快速开始、常见用法、重要限制及更多文档，不机械套齐章节。
  长文提供简短导航，架构只保留理解使用和修改所需的边界，细节链接已有文档。
  不把 README 写成内部交接、验收流水账、完整 API 手册或未来功能清单。
- 有助于理解时使用真实截图、GIF、输出或小图，并提供说明与必要的替代文字。
  复用适用的现有素材，控制体积。演示、示意与实测分别标明，不伪造运行效果。
  徽章只保留真实相关的状态并链接证据，不强制增加 banner、动画、星数或装饰。
- 功能、平台、性能与安全表述都须有对应范围。区分静态检查、本地运行、远端 CI
  和已发布产物。比较说明任务、版本与条件，保留限制和反例，不用测试数量代替质量。
  未实现、mock、实验、未知与未验证能力不能写成可用承诺。
- 给出确实存在的文档、问题反馈、贡献及许可入口。公开 README 使用仓库相对链接
  或可访问的公开地址，不依赖本机绝对路径、忽略目录或相邻私有 checkout。
  不虚构联系渠道、许可、贡献者、下载入口或公开部署。
- 交付前检查变更涉及的链接、图片、标题锚点和多语言语义一致性。
  新增或改变的命令、示例在适当的临时样本中实际核对；未能验证时明确说明。
  不为纯文案修改启动无关服务或完整测试，不自动安装工具、提交、推送或发布。
  中文成稿用 humanizer-zh，英文用 stop-slop，重要对外稿件及实质性英文文件编辑再用离线 Harper，并人工复核技术词。
